# Stem storage incident and withdrawal

The legacy desktop preparation implementation retained both uncompressed WAV components and the same audio as SQLite BLOBs. A library-wide batch could repeat this without an aggregate quota. On the owner laptop, prepared-stems reached about224GiB; this was generated audio, not source music. The running installation was Beta1, not the newly published scratch update.

Immediate safety change: legacy preparation and archive restore are withdrawn at the shared entry points, before creating a folder or spawning a process. Installed add-ons and AMP_STEM_PYTHON cannot override the withdrawal. This is a safety disable, not an implementation of a new realtime engine. Lab separation also remains unavailable through the withdrawn runtime. Ordinary playback, original audio, metadata analysis and playlists remain available. Library organization skips legacy stem relocation rather than blocking music organization.

Cleanup is limited to the generated settings/prepared-stems folder. Do not delete the settings root, music, playlists or metadata catalog. Stop the old app first. This source change does not stop or modify an older running executable, and no automatic deletion is added.

## Verified external behavior

VirtualDJ officially separates audio on capable hardware, supports on-demand processing, and controls saving independently. Its documentation warns that saved prepared stems can occupy aboutfour times the original track size. https://virtualdj.com/manuals/virtualdj/interface/stems2.html

Mixxx documents loading STEM tracks generated by third-party tools; it is not evidence of a storage-free realtime separator. https://mixxx.org/news/2025-05-11-mixxx-2_6_beta-released/

## Replacement acceptance (not yet implemented)

- No library-wide stem generation or automatic saved audio.
- On-demand isolation only when the DJ actually requests a part; ordinary playback/analysis never triggers separation.
- Bounded working buffers and an explicit aggregate budget. Decoded blocks must be released when the deck unloads.
- No automatic WAV-plus-database duplication. Audio is not metadata.
- Optional persistent preparation must be a separate deliberate export, with size disclosed, a configured location and a hard quota.
- Server-offloaded preparation is explicit; do not silently use the laptop as a library processing worker.
- Measure source-sum quality, artifacts, startup delay, sustained realtime factor, CPU/GPU/RAM and disk high-water on Windows/Linux before calling it realtime or shipping it.
- Original recordings are read-only; never claim actual stem isolation without audio separation underneath.
