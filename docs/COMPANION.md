# Companion show control — implemented desktop milestone

Companion directs commands; AMP DJ performs; AMP Library prepares and approves. Node-RED → OnTime → Companion → AMP Verse remains unchanged. This repository does not reconfigure or send messages to the office automation systems.

## Connect

Start the updated desktop app. Its control gateway listens on `127.0.0.1:8790` by default. In Library, expand **Companion / show-control connection** to change the listen address, set an optional password, and restart or stop the connection. Audio remains owned by the local engine and continues when the gateway or a client disconnects. `AMP_CONTROL_BIND` and `AMP_CONTROL_PASSWORD` provide launch-time configuration; `AMP_CONTROL_DISABLE=1` suppresses automatic startup. For trusted-LAN operation, explicitly bind `0.0.0.0:8790` and use the desktop's LAN address in Companion. The listener is HTTP; it does not configure routing, firewall rules, Internet exposure or TLS.

Use Bitfocus's [Generic HTTP Requests module](https://bitfocus.io/connections/generic-http) for the implemented integration. It supports POST actions, response extraction and HTTP feedback. This is a working generic-module API integration, not a packaged/native AMP Verse Companion module. Importable Companion pages, SDK-specific presets, OSC/MIDI and controller mappings are separate work.

- Base URL: `http://DESKTOP-IP:8790`
- Action method: POST
- URI: `/api/v1/command`
- Headers: `Content-Type: application/json`, plus `x-amp-password: YOUR_PASSWORD` when configured
- State feedback: GET `/api/v1/state`
- Song/cue/playlist catalog: GET `/api/v1/catalog`
- Passive WebSocket feedback: `ws://DESKTOP-IP:8790/api/v1/events`, using the same password header when enabled

The state JSON contains an `amp` object. Map its properties into Companion variables such as `amp.current_song`, `amp.playback_state`, `amp.active_deck`, `amp.remaining_time`, `amp.playlist`, `amp.mix_style`, `amp.target_energy`, `amp.current_energy`, `amp.progression_remaining`, `amp.auto_dj_enabled`, `amp.auto_crossfade_enabled`, `amp.fade_state`, `amp.fade_progress`, `amp.master_level` and `amp.manual_dj_locked`. Unknown artist/energy/cue data is null, not invented. On transport failure, the client should report disconnected; do not configure reconnect actions that send Play or recall a scene.

## Request IDs and acknowledgments

Every physical button press needs a fresh `id`. Use a persisted custom counter with a unique client/session prefix, or a UUID generated by the client. Retrying that press must reuse the same JSON and ID. Do not use one static ID for a permanent Companion button: its later presses would be treated as retries. The server retains the latest 512 command results per running gateway. Reusing an ID with a different action returns HTTP 409. A duplicate pending request shares its original result. Restarting the gateway clears that bounded retry history. WebSocket reconnection itself is passive and sends no commands.

Success reports `ok: true, status: "accepted"`: validation passed and the performance engine accepted the operation. It is not proof that a decoder has buffered or a fade has completed. Read the subsequent engine state for those facts. Failure reports `ok: false` with an error, or rejects malformed JSON with HTTP 422. The bounded UI queue expires commands that have not executed within four seconds, so a stalled UI does not execute a late show action after the client has timed out.

Song title lookup requires an exact case-insensitive match; ambiguous titles fail. Prefer catalog IDs. Song IDs hash the root-relative path with forward-slash separators: they survive a root relocation and analysis updates, but file/folder renames change them. Cue IDs and explicit hot-cue numbers come from metadata; legacy manual cues receive unused numbers without changing positions. Prefer cue IDs when sharing commands between installations. Playlist IDs are saved independently of their display names.

## Playback behavior

Load Only chooses an idle deck and rejects an explicitly busy target. Auto Fade also refuses to replace a playing incoming deck. Play Now is the explicit cut/start mode. Prepared crossfades wait for incoming PCM; the outgoing deck keeps playing while it loads. The current milestone uses the existing buffered equal-power crossfade and approved cue bounds. It does not claim phase-locked or phrase-classified mixing.

`mix_next` with `immediate:false` waits for a saved transition/grid candidate or the approved outgoing boundary; `immediate:true` requests the buffered transition now. Stop is separate and immediate. Fade Out only stops after reaching its target when `stop_after:true`. Duck records the prior master level once; Restore fades back to that level. Manual DJ Lock rejects automatic selection, progression and takeover commands; explicit playback Stop/Pause/Play, sampler and manual crossfader actions remain available.

## Smart performance

Library owns editable defaults for Recognition, Walk-In Music, Meeting Open, Everyday Music, Background Music, Break Music, Closing Music and Custom, plus new user-defined playlists. Rules include source folders, allow/exclude/preferred IDs, assigned recognition music, style, energy, repeat policy, fallback and an optional saved progression. Saving writes `.ampverse/show.json` in the library root. DJ loads a runtime copy; Library changes do not silently rewrite that active copy.

The selector combines harmonic/tempo compatibility and energy, with strict folder/allow/exclude eligibility. Recent-repeat behavior is configurable: Stop or relax only the recent restriction when every eligible candidate is recent. Explicit recognition assignments win but still respect eligibility. A runtime progression uses the actual loaded song's prepared energy as its starting point and advances only when the song transition completes. Unknown energy rejects progression rather than inventing a starting level. The nearest eligible song can differ from the requested target.

Style currently controls prepared manual build/drop cue preference (Hype) and fade duration (Hype 3 s, Steady the operator's mix duration, Chill 10 s). Chill retains approved song bounds. Automatic verse/build/drop classification, section-energy-based segment selection, downbeat/phrase locking and deliberate musical-lull planning remain unbuilt; the three style names are not a claim that those algorithms exist.

## Quick client

`tools/amp_control.py` generates a UUID and retries transient network failures with the same ID. Example:

```sh
python tools/amp_control.py '{"action":"pause","deck":"auto"}'
python tools/amp_control.py '{"action":"load_smart_playlist","playlist":"background","execution":"auto_fade"}'
```

The recommended Companion primary page maps Playback, Music, Transitions, Smart DJ and Extras to these requests. The optional eight-button page can map Play, Pause, Fade Out, Auto Fade, Call Song, Recognition, Everyday and Auto DJ. Place crossfader and sampler controls on a secondary page. These are setup instructions, not a fabricated `.companionconfig` import file.
